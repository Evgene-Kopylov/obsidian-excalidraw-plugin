# Задача: padding-слайдер для `area=` вставок на холсте Excalidraw

## Цель

Добавить возможность менять `padding` у `area=` вставок прямо на холсте Excalidraw — так же интерактивно, как это уже работает в режиме чтения markdown-заметки.

## Контекст

- Сейчас попап работает только в markdown-режиме чтения: `MarkdownPostProcessor.processInternalEmbed()` оборачивает `.internal-embed` через `wrapWithPaddingPopup()`.
- На холсте `![[file#^area=ID,padding=N]]` становится `image`-элементом Excalidraw. Ссылка хранится не как `![[...]]` в теле заметки, а в секции `## Embedded Files`:

  ```
  <fileId>: [[path#^area=ID,padding=N]]
  ```

- Поэтому таргетинг и сохранение на холсте отличаются, но сам слайдер-UI можно переиспользовать.

## Проверенный подход

### 1. Вынести UI в переиспользуемую функцию

В `src/shared/PaddingUI.ts` выделить:

```ts
openPaddingPopup(doc, anchor, initialValue, onCommit)
```

Функция рендерит попап со слайдером, дебаунсит `onCommit` на 400 мс при drag/клике/колесе, сохраняет при `pointerup` и при закрытии по клику мимо. Существующий `wrapWithPaddingPopup` (markdown-путь) должен продолжать использовать эту же функцию.

### 2. Триггер на холсте

В `ExcalidrawView.onChange()` при выделении ровно одного `image`-элемента, у которого:

```ts
this.excalidrawData.getFile(el.fileId)?.filenameparts?.hasArearef === true
```

— открывать попап. `doc` брать из `contentEl.ownerDocument` (корректно для popout-окон).

> Временная кнопка «Padding» — только для отладки; в чистовой версии убрать.

### 3. Сохранение — как в заметке, через `vault.process`

`onCommit` вызывает:

```ts
await app.vault.process(file, (data) => {
  const marker = `${el.fileId}: [[`;
  const lineStart = data.indexOf(marker);
  // ... границы строки по "\n"
  // внутри строки найти `#^area=<blockref>`
  // заменить на `#^area=<blockref>` + (value === default ? "" : `,padding=${value}`)
});
```

Ключевые детали:

- `default = plugin.settings.exportPaddingSVG`.
- Старый реф захватывать через `/^#\^area=[^|\]]*/` — это покрывает и существующий `,padding=N`, и алиас `|100%`.
- `fileId` уникален для встроенного файла, поэтому строка `<fileId>: [[...]]` уникальна — `nthIndexOf`/подсчёт вхождений не нужен.

Почему это работает: правка текста файла через `vault.process` → Obsidian сам перерисовывает затронутый файл, а дебаунс 400 мс даёт интерактивность. Перерисовывается только целевая вставка.

## Критерии приёмки

- [ ] Выделение `area=` image-элемента на холсте открывает попап со слайдером.
- [ ] Движение слайдера обновляет `padding=N` в `## Embedded Files` на лету, а не только при закрытии.
- [ ] Перерисовывается только целевая вставка; остальные не трогаются.
- [ ] Несколько `area=` вставок на одном холсте работают независимо (таргетинг по `fileId`).
- [ ] Markdown-режим чтения продолжает работать без изменений.
- [ ] Popout-окно: попап открывается в документе owning-window.
- [ ] `npm run build` проходит.

## Замечание

Позиционирование в проверенном варианте было фиксированной точкой. Для чистовой версии — привязать к экранным координатам элемента (`scene → viewport`).
